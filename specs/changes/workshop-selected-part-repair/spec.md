# 工坊只修理选中的渔轮部件

Status: done

## Problem Statement

渔轮三个部件同时磨损时，只选择一个部件修理也会恢复所有部件并按整机磨损收费，超出了玩家选择范围。

## Solution

报价和实际修理均只覆盖选中的部件。未选部件的型号、耐久与制动力保持不变；本体显示按剩余部件状态汇总。重复提交已修好部件返回当前装备且不再扣费。

## User Stories

1. 只修齿轮时，摩擦片和轴承继续保留原来的磨损。
2. 多选部件时只修所选部件，费用为各选中部件报价之和。
3. 修摩擦片时恢复其额定制动力和耐久，其他件不变。

## Implementation Decisions

- 修改 `hWorkshopDiag` 的逐部件报价和 `hWorkshopOrder` 的同型号修理、费用校验、本体耐久计算。
- 保留事务、回执、零费用对象响应、鱼竿修复、不同型号换件及金币限制；不改变表结构与静态库。
- 本体仅在确实选择本体修理时直接恢复；选择内部零件时按修后零件聚合，不能强制为 1。
- 客户端基线 4.0.25034；结构沿用 21/2、21/3、21/4 现有协议，字段类型不变。
- 本 spec 取代 `reel-friction-life-model` 中关于同型号工坊订单进行整机保养的旧行为描述。
- 后续 `workshop-preview-confirm` 修正预览/支付边界及微小磨损报价；21/3 只预览，21/4 才提交所选部件修理。

## Testing Decisions

- 真实 SQLite：齿轮 80%、摩擦片 20%、轴承 50%，分别单选及多选修理，验证未选字段不变、所选恢复、费用分别为 100/400/250。
- 21/2 逐部件报价与实际扣费一致；验证摩擦片制动力与镜像耐久不一致时仍按真实制动力报价和恢复。
- 回归重复提交无重复扣费、失败回滚、低报价拒绝、鱼竿及换件流程。
- 真实 SQLite + 协议请求：本体修理仅在内件全满时允许；与内件订单组合或存在未修内件时，预览与确认均拒绝且不改装备、余额。
- 运行定向测试、全量测试、vet、build、doccheck，部署后核对运行版本。

## Out of Scope

不重新标定官服价格，不改变同型号修理与异型号替换分类，不恢复之前已经修好的磨损。

## Evidence

- [事实] `TestWorkshopRepairOnlySelectedReelPart` 覆盖三个磨损件中只修一个的行为，回滚实现后因未选部件被修改而失败。
- 官方说明支持按部件选择维修：https://rf4game.jp/userguide/ 。精确协议计价仍沿用本地现有倍率，不声称已完成官服定价校准。

## Validation

- 新增单选测试在旧逻辑下三组均因未选部件被修改而失败；修复后通过。
- 单选、多选、重复确认、零费用、报价、摩擦片实际制动力、鱼竿换件及本体/内件越权组合定向测试通过。

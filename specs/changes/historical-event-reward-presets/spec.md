# 历年活动奖励预设

Status: done

## Problem Statement

后台只有九周年奖励预设，其他已支持的周年庆和新年分支需要逐项手动配置。物品同名但年份不同，直接复用九周年配置会发错纪念商品。

## Solution

扩展现有预设选择，按年份填充已开启分支的空缺阶段，并提供填入全部已收录预设的入口。七、八周年按历史奖励界面及玩家资料整理，九周年保留官服预览映射。用户确认未取得逐阶段依据的新年奖励留空并显示待核实，保留官方还原目标。

## User Stories

1. 管理员可以选择年份或全部已收录预设，查看来源和覆盖范围，检查后保存。
2. 已有阶段配置、未保存的编辑和未启用分支保持原样；填入操作不直接保存或发奖。
3. 七、八、九周年的普通与特别版均覆盖七个阶段及全部完成额外奖励；原有奖杯机制继续独立发放。

## Implementation Decisions

- 每年一份 JSON，继续使用 event_stage_gifts 与现有事务、领取标记和会员处理，不修改协议或经济链路。
- 管理页增加年份选择及来源说明。新年 2024/2025/2026 资料不足时不可填入，显示缺失状态。
- 每项一件完整商品；堆叠饮品按静态商品份数，礼盒沿用静态内容。预览截图不证明领取数量及隐藏属性，需明确说明。
- 实施顺序：增加预设覆盖/物品合法性回归 → 资源与选择界面 → 全阶段领取、重复领取与 UI 回归 → 全仓门禁和评审。

## Testing Decisions

- 嵌入资源按清单检查全部阶段及完成奖励，真实静态库验证商品可配置。
- 真实玩家测试库逐阶段完成、检查领取数量及标记、重复巡检不增发。
- UI 验证选择年份、填入全部、保留草稿、未启用分支不写、待核实预设不操作；1280/360 宽度。
- go test ./...、go vet ./...、go build ./...、doccheck。

验证结果（2026-11-17）：全量 `go test ./... -parallel 4`、`go vet ./...`、`go build ./...` 通过。真实静态库预设与七、八周年阶段发放回归通过；Playwright UI 在 1280/360 宽度通过（12.2s）。doccheck issues=0，既有 bite 文档长度软提示 1 条；独立评审无阻塞问题。尚未部署到运行服务，客户端实机奖励展示及领取未验证。

## Out of Scope

修改实际玩家任务进度；无依据地声称复原全部新年奖励；官服实例隐藏属性；修改启动时默认配置。

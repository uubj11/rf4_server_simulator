# 自动补充窝料与鱼片

Status: done

## Problem Statement

食笼窝料投放后，即使背包还有同种库存，也不能自动装填（#399）。柳叶亮片鱼片耗尽后，拟饵自带钩不在竿直属组件中，原补饵流程会丢弃补饵请求（#505）。

## Solution

窝料、PVA 和单钩鱼片耗尽时记住原装配位置，在已有收竿和抛竿准备入口从匹配库存补一份。已占用、没有库存或相关钩、食笼已拆卸时，不替换其他组件。

## User Stories

1. 连续抛竿时自动使用背包内同种窝料，无需每次手动重装。
2. 柳叶亮片挂鱼片，中鱼收竿后补回鱼片，亮片与鱼钩保持不变。
3. 写入失败不丢库存、不生成免费饵，重试或重启不重复补充。

## Implementation Decisions

- consumeBaitEvent 随消耗事务记录实际父对象、品类、Extra、物品定义和配方；鱼片另外保留钩位。
- reloadBaitForCast 调用事务化槽位补充逻辑，库存拆分、实例父引用、f5、rig_component 和补充记录删除整体提交。
- 同物品定义的窝料仍须匹配配方；无匹配库存时不替换为其他饵料。
- 其他天然钩饵及多钩鱼片沿用既有 rebait 路径，不重构通用手动装配。
- 无迁移、不改变协议编码；复用 pushBaitChange 的库存移除及最新物品树推送。
- 新记录存于 rod_setting；旧 rebait 记录继续由旧路径处理，回退代码后可手动补饵。

## Testing Decisions

- SQLite 回归覆盖窝料、PVA、柳叶亮片鱼片、直属钩鱼片，以及空库存、已占槽、重复调用、消耗事件重放、组件保护和持久化重开。
- 在新增子实例、扣减来源数量、父组件更新、删除补充记录四处注入写入失败，验证整体回滚及重试。
- 配方测试确认同物品定义的不同配方不混用，子实例继承原配方。
- 初始 4 份，首次挂 1 后背包 3；消耗挂载一份不扣背包，补充后背包 2、挂载 1。
- 定向测试：go test ./internal/gameserver -run 'TestSlotBaitRefill|TestBait' -count=1。
- 交付检查：go test ./...、go vet ./...、go build ./...；实际结果记录于 PR。
- 用户已反馈消耗正常；自动补装、异常回滚、拆钩及空库存等行为由自动化覆盖，不将其描述为全部实机验证。

## Out of Scope

不改普通装配、制作配方、鱼获奖励或协议结构。钓组内窝料自定义名称显示问题独立处理，本次不包含该问题的候选修复。

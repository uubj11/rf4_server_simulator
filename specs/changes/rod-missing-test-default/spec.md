# 缺 Test 区间的竿按保守折减参与抛投

Status: ready

## Problem Statement

静态竿库中约两成竿（218/1043）没有登记 Test 区间。抛投计算里"竿未登记 Test"被当作"无限承重"处理（系数 1.0），结果这批竿抛得比登记了合适 Test 区间的同类竿更远，与竿的实际物理特性不符，也让玩家无法从抛投距离上区分竿的规格差异。

## Solution

竿未登记 Test 区间时，抛投重量系数取偏保守的固定折减 0.85，使缺数据竿略弱于登记了合适 Test 区间的竿，而不是与它们持平。

## User Stories

1. 作为玩家，我希望未登记 Test 区间的竿不要再享受满额抛投系数，以便竿与竿之间的距离差异反映真实规格。
2. 边界：已登记 Test 区间的竿（含区间内、超重衰减两条路径）行为完全不变；payload 为 0 的既有 0.80 分支不变；本系数只影响抛投距离，不参与断线或炸杆判定。

## Implementation Decisions

- 只改 `internal/gameserver` 的 `rodTestWeightFactor` 中 `testMaxG <= 0` 分支：返回值 1 → 0.85。
- 不改 Test 区间内曲线、超重衰减、`rodOverTestRatio` 及任何其他抛投修正器。
- 不改表结构与协议字段，客户端兼容基线为 4.0.25034；回滚代码即可恢复。
- 数值依据：[推断] 0.85 取登记竿区间内典型载荷（约在 Test 参考值附近，系数 ≈0.845）之上、峰值之下的一档保守值；未做官服逐竿实测对比（无法取得），未验证官服对缺 Test 竿的真实处理。

## Testing Decisions

- 测哪一层：单元（纯逻辑），直接调用 `rodTestWeightFactor`。
- 期望值来自哪：已知良好字面量 0.85（本 PR 定义的新常量行为）；对比项 `rodTestWeightFactor(8, 5, 30)` 的实测值 0.845 来自手算样例（0.80 + 0.12·ln(1 + 8/17.5)）。
- 回归联动：`TestCastCalibrationBands` 等标定带断言使用的竿均登记了 Test 区间，全量测试已确认不受影响（`ok 218.453s`）。

## Out of Scope

- 不补静态竿库的 Test 区间数据（数据采集与校对另行处理）。
- 不处理线杯系数方向问题（维护者已说明需先逐档实测再定方向）。
- 不做整体抛投重标定（#465 已关闭，官服手感方向由 #464 承接）。

## Further Notes

- [事实] 静态竿库 1043 根竿中 218 根（20.9%）未登记 Test（#465 评审中由维护者复核确认）。
- [事实] main 当前 `testMaxG <= 0` 分支返回 1。
- [推断] 缺数据按 0.85 保守折减后，这批竿的距离约下降 15%，仍显著高于"抛在脚边"的下限场景。
- [假设] 官服对未登记 Test 竿的真实处理未知；若后续取得官服实测证据，可再校准该数值。

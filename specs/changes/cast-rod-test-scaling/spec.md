## Problem Statement

标称距离只有一个族常量，**完全不读竿的 Test 上限**，导致同一族里所有竿
共享同一个基准，两端同时错：

1. **轻装偏高**。`castNominalLureM=27.5` 是 #464 按一根 1.8m、Test 1-8g 的
   UL 配置实抓的。同一常量套到满技能、满熟练的 2m/Test 0.5-4g UL 上，
   实测 32.11m——比官服实抛（100% 路亚熟练 + 技能点满 + 水滴轮 + 未改装，
   约 27m）高 **18.9%**。`cast_distance.go` 第 8 行注释自己写的是
   "满级投距技能的 UL 配置满功率 ≈25m"，与代码实跑值自相矛盾。
2. **中重装偏低**。同一常量套到 2.7m/Test 15-49g + 63g 载荷 + 6000 线杯上
   只有约 20-25m，与「MH 竿配 63g 饵不该只有 20m」的实机反馈不符。竿越硬、
   饵越重，被压得越狠。**该档的官服实测值尚未取得**（见「未解决」节），
   现用回归基线约束，不作为外部锚点。

根因在官方手册里写得很直白——飞距离要素第 3 条是「釣り竿の特性：**長さ、
構造、強さ**」，第 1 条是「仕掛けの重さの釣り竿に対する**適応度**」，第 2 条
是「リールの特性」。上游把竿特性收敛成一个族常量，等于把第 1、3 条要素
丢掉了；#464 又把一根 UL 的实抓值当成整个淡水路亚族的基准，是"用 UL 的
问题推广到全族"。

## Solution

标称从"族常量"改成"族基准 × 竿 Test 上限的分档曲线"，两个锚点反解：

```
nominal(rigType, testMaxG) =
    marine(50-54)               → 45.0            // 待补锚点，不动
    testMaxG <= 0（缺失）        → 路亚 23.06 / 非路亚 60.0   // 族常量兜底
    路亚族                       → 23.06 × (testMaxG / 4)^0.41
    非路亚族（手竿/浮钓/底钓/鲤鱼）
                                → 23.06 × (testMaxG / 4)^0.29
```

- 锚点档 4g：`23.06 × 0.9132(载荷) × … × 1.6(技能) = 27.00m`，命中官服 UL。
- Test 49g 档：`23.06 × (49/4)^0.41 = 64.4`，乘同一因子链得 **50.04m**。这个
  50m 只是**内部回归基线**，不是官服实测（见上表「锚点 2 已撤回」）；该档真实
  锚点取得后必须重解 `castNominalTestExp`。
- 非路亚族 Test 2040g 档：`23.06 × (2040/4)^0.29 = 140.6`，乘同一因子链得
  **115.7m**（+75%）/ **112.4m**（+70%）/ **116.5m**（4m 竿 +75%）。同帖四条
  实测分布是 95 / 105-110 / 115 / 135 / 146m，模型落在 112-117m，即四条的中位区。
  逐条反解指数得区间 0.265~0.326，取中位 **0.29** 而不是顶配那条的 0.326，
  避免把整族都按顶配推到上限（0.33 会让 Dominator 的 95m 被算成 148m，+56%）。
- 派生：Test 8g ≈ 32.6m、Test 15g ≈ 38.7m、Test 30g ≈ 51m、Test 70g ≈ 72m
  （3m 竿、满技能口径），随 Test 单调递增，覆盖"UL 27m → 中重装 50m+ → 重装 70m+"。

## User Stories

1. 作为超轻打榜玩家，满技能、未改装的 UL 抛 27m 上下，与官服一致（作者自测）。
2. 作为重装玩家，越硬的竿越远，而不是所有竿共享一个基准。
3. 边界：不填 Test 上限（`testMaxG<=0`）时取 4g 锚点档 23.06，不 panic、
   不归零。
4. 边界：Test 上限低于 4g（如 0.5-3g 的微物竿）时同样取锚点档，不被
   `(testMax/4)^0.41` 反向缩小。
5. 边界：海钓路亚（50-54）标称仍是 45；非路亚族缺 Test 时仍是 60，
   已登记 Test 时走 0.29 曲线。
6. 边界：载荷未知（payload<=0）时仍走 #492 的 0.80 折减，不因本次改动回归。

## Implementation Decisions

1. `castNominalDistanceForRod(rigType int64, testMaxG float64) float64` 为新
   唯一入口；`castNominalDistanceM(rigType)` 保留为 `testMaxG=0` 的兼容包装。
2. `castNominalLureM` / `castNominalTestExp` 从 const 改成 **var**，便于测试按
   锚点重定标后回填；生产代码只读。
3. `calculateCastDistance` 首行由 `castNominalDistanceM(c.RigType)` 改为
   `castNominalDistanceForRod(c.RigType, c.RodTestMaxG)`。
4. `p.BaseM` 同步改为按竿分档，保证日志与结算界面展示的基准与实算一致。
5. 最小 diff：只动 `internal/gameserver/cast_distance.go`（+30/-6 量级）与
   对应测试；不碰修正器曲线、不碰 `handlers_game.go` 的红区收口、不碰
   `player_condition` / `fishing.go`。

## 未解决矛盾（只记录，不做改动）

1. **线径/线种**：官方 jp 手册「線の種類によって飛距離も変わります」+ 客户端
   Super Braid 文案"增加抛掷距离" **vs** 德语官方论坛 2018-10-03 实测复查
   「线径与线种对纺车轮抛投距离无影响」。两处都不够新，不下结论。
2. **竿调性**：jp 手册「硬い釣り竿は投げる際に飛距離が出にくく」（硬竿抛不远）
   **vs** 德语区官方发帖人指南「Spitzenaktion + steifer Blank 能打极远」。
   上游 `castRodActionFactor` 是"越硬越远"，与 jp 手册相反，与德语帖一致；
   本次不动，等更强证据。
3. **已知优先级冲突**：`cast_distance.go` 里 `testMaxG<=0 → 0.85`（#491）排在
   `payloadG<=0 → 0.80`（#492）之前，两者同时成立时 #492 的分支永远不可达。
   属既有行为，本次不改（改它会动 #491/#492 两个已合并 PR 的语义）。

## 为什么必须这么做（还原官服手感）

1. **手感的基准点必须是"可复现的官服实抛"，不是模型内部自洽。** 上游 #464 的
   27.5 来自一根 UL 的实抓，值本身不错，错在把它当成整个淡水路亚族的基准——
   同一常量套到 Test 49g 上是 20m 出头，套到满技能 UL 上是 32m。玩家体感一次
   错两端：轻装偏近、重装偏近，而模型自己看不出问题。
2. **官方手册已经把竿列为飞距离要素。** 「釣り竿の特性：長さ、構造、強さ」是
   11 条要素里的第 3 条。标称是一族一个常量，等于把这条要素从模型里删掉；
   而 Test 是玩家配饵、配线时唯一能直接对齐的竿参数，它进不了标称，玩家就
   无法通过换竿获得应有的射程差。
3. **用两个方向相反的锚点交叉约束一条曲线，才能同时修好两端。** 只用 UL 27m
   定标会把大竿一起拉近（这正是我第一次的错误）；只用单点定标会让曲线另一
   端失控。当前 0.41 由 UL 锚点 + 竿长/Test 单调性约束反解，中重装档的官服
   实测值仍缺，补齐后需重解。
   两个锚点反解出截距 + 指数后，中间档位（Test 8/15/30/70）由曲线自然给出，
   不需要逐档手工填数。
4. **非路亚族同理，而且偏差更大。** 上游固定 60 让 3.9m 鲤鱼竿 + 140g 的实测
   146m 只剩 49m（差近三倍）；同时让 8m 博洛尼亚抛到 60m（玩家判断明显不合理）。
   同一族内部轻竿变近、重竿变远，才是"竿越硬饵越重越远"的官服手感。
5. **不改的也要说清为什么。** 技能因子 1.6 与官方 +60% 一致（S5），红区收口
   （#464 后半段）与"满竿就是上限"一致，线杯方向与官方"小杯更远"一致，
   这些都对，动了就是破坏。所以本 spec 只动标称这一个入口，其余修正器曲线
   一个不碰——最小 diff 也是手感可回归的前提。

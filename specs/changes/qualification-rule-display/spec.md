# 对齐资格任务条件显示

Status: done

## Problem Statement

命令 28/1 下发的 5007 资格规则目前只填写规则编号、目标数量、部分钓组/竿型及动画条件，
其余数组为 `null`，重量、鱼种、水域、饵料、线型与线强等字段为零。客户端因此只能显示
不完整的任务条件，且 `null` 数组不符合客户端遍历要求。

## Solution

使用客户端版本 4.0.25034 登录官服后反序列化得到的 168 条永久资格规则作为事实来源，
把每条规则的 28 个字段整理为精简静态表。28/1 仍返回既有 5007 对象，不改变命令、对象
类型或字段顺序；只补齐字段值，并把所有空数组按其真实容器类型发送为空数组。

## User Stories

1. 打开任一永久资格任务时，客户端显示与官服相同的目标数量和条件参数。
2. 没有限定鱼种、地图、饵料或枚举条件的任务仍可安全打开，不因 `null` 数组异常。
3. 典型任务 4502 显示超轻伸缩竿、星及以上、500 克以上、尼龙/碳线及 1.5 公斤线强上限。

## Implementation Decisions

- 静态表只保存 5007 的结构化条件值，不提交抓包、登录凭据、玩家数据或诊断导出文件。
- 枚举数组沿用普通 U32 数组；字符串数组使用协议的字符串数组容器，空值也发送空数组。
- 5007 中以 U32 承载的 float32 范围字段按原始位模式保存和发送，保留正负 float32 极值。
- `qualificationRule` 只从全量静态表构造对象；测试要求 1..8 分支、7 个阶段、每阶段 3 条
  共 168 个规则全部存在，避免静默退回不完整规则。
- 本次只对齐 28/1 的静态规则显示，不改资格事件分类、计数、完成条件、奖励或玩家进度。

## Testing Decisions

- 校验 168 个规则编号完整且无重复，每条均构造 28 个字段。
- 编解码后验证所有枚举数组与字符串数组均非 `null`，并保持正确容器类型。
- 逐字段对比生成的 168 条 5007 与精简官服事实表。
- 单独断言 4502 的竿型、竿强度、鱼档位、重量、线型及线强字段。
- 执行 `go test ./...`、`go vet ./...`、`go build ./...` 与 `go run ./tools/doccheck`。

## Out of Scope

- 修正各资格任务的服务端判定与目标计数。
- 重算或清理已有玩家资格进度。
- 活动任务、资格奖励和本地化文本修改。

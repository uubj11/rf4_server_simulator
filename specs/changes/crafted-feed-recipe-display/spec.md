# 成品诱饵配方与 PVA 材料选择

Status: done

## Problem Statement

玩家制作干混合后，在 PVA 制作页选择材料会一直停留在加载状态；成品干混合、普通诱饵及 PVA 棒缺少可供客户端展示的配方内容。

## Solution

成品携带实际使用的配方，材料选择与配方详情可以读取同一份内容。已保存用料的旧干混合和窝料在读取时恢复展示；新 PVA 成品保留所选干混合的配方，原料耗尽后仍可查看。

## User Stories

1. 玩家能在 PVA 制作页选择背包内的干混合。
2. 玩家能查看干混合、普通诱饵和 PVA 棒的实际成分。
3. 同名但配方不同的干混合制成 PVA 后仍各自保留配方；重连、拆分挂载后内容不丢失。
4. 无用料记录的物品保持合法空列表，不凭空生成历史配方。

## Implementation Decisions

- 修改 `internal/gameserver` 的成品物品投影及制作入口；按 `tools/proto.ps1` 核对 4/5、9/1 及其物品嵌套字段。
- 配方数组与 PVA 内嵌窝料对象的具体类型以客户端读取点和类型注册表为依据，不使用合成的数组编号。
- 不改静态库、表结构或迁移。旧干混合与窝料从既有 `groundbait_recipe` 投影；PVA 的配方快照写入其物品字段，与扣料和产出共用制作事务。
- 客户端基线为 4.0.25034；保留有效的已有物品配方。回滚代码不删除原用料记录。

## Testing Decisions

- 存储和物品投影：真实 SQLite 夹具，覆盖旧库存用料恢复、空列表、配方分组和有效快照保留。
- 制作链路：两组不同配方的同名干混合分别制作 PVA，检查响应与存档中的实际配方，并覆盖原料耗尽、拆分挂载。
- 协议编解码：断言经核实的数组类型和元素字段，验证 4/5、9/1 嵌套数据可回环。
- 回滚修复后，空配方数组和 PVA 原料快照断言应失败。
- 完成后运行 `go test ./...`、`go vet ./...`、`go build ./...`、`go run ./tools/doccheck`。实机验收由用户执行。

## Out of Scope

不调整鱼口、配方产量、材料价格、技能收益或交易幂等机制；不猜测缺失历史记录的成分。

## Further Notes

- [事实] 4.0.25034 实机选择干混合时出现加载停滞，客户端材料列表初始化报空引用。
- [事实] 成品库存的用料记录存在，而物品配方数组为空；物品下发入口尚未投影该记录。
- [事实] 客户端说明读取器直接遍历三配方数组，实机异常栈定位到该方法；元素注册码与分组已通过运行时注册表和读取点核实，结论见 `docs/debugging-workflow.md`。
- 用户已实机确认配方正常显示、PVA 可正常制作；实际重连与拆分挂载后的显示尚未取得实机验证结果。旧 PVA 若仅记录干混合定义名而没有实例配料，显示合法空配方，不推测历史成分。

# 资格任务判定与进度结算修复

Status: done

## Problem Statement

资格任务的部分条件与实际装配、任务定义不一致：手竿任务未统一限制伸缩竿，主线被从钓组组件
而非竿的专用字段读取，基础经验与加成经验混用，海洋任务缺少地图限制并存在钓组、鱼种名单
及计数口径错误。三个永久任务的完成数量仍采用推测值，和已核对的条件显示不一致。

活动进度和奖杯没有检查开关、所选分支及结束时间；指定夜间范围使用宽泛夜间标记，
两条备选完成路径缺少独立证据。多钩额外鱼没有进入资格判定，也没有返回最终累计进度。

## Solution

复用已有资格事件、Counted 过滤与去重、结算事务、鱼 GUID 回执和 5003 进度通道修正条件及计数。
不改变资格树结构、handler 分发或测试框架，不引入客户端模块、数据库表或新协议类型。

## User Stories

1. 手竿全部 21 项要求伸缩竿，其他竿型不推进；超轻、线型、线强等条件仍分别判断。
2. 海洋任务只在挪威海推进；未指定钓组的任务允许普通路亚，明确指定的钓组和鱼种条件继续生效。
3. 飞德五种钓组、人面鲤五种鱼、底部发丝九种钓组任务分别按 5/5/9 完成。
4. 活动关闭、未选中或结束后不再计数或新发奖杯；永久任务不受活动开关影响。
5. 指定时间条件取咬钩时间，搏鱼跨时段或服务重启不改变判断。
6. 两条备选完成路径分别累计，不能各取一条凑成完成。
7. 同杆多尾鱼分别计数，结算响应返回最终进度；重复请求不重复计数或扣饵。

## Implementation Decisions

- 手竿限定竿型 3 和浮钓钓组；4501 昆虫饵类为 7；4603 使用十种指定白鲑；
  4402 使用基础经验；4502 要求超轻、尼龙或碳线及不超过 1.5 公斤的线强。
- 主线从竿实例专用 csLine 字段读取，前导线从 f5 读取；保持已有的最小已知承力值语义。
  线强未知仍不满足上限条件。
- 海洋任务按挪威海地图过滤，并修正 8202、8302、8402、8403、8601、8603 的明确条件；
  8502 按鱼 GUID 计三尾，不要求三个鱼种。
- 未指定钓组的海洋任务不采用公共 50..59 列表作为额外限制；现有任务列表构造处将其
  5007.Idx9 设为空枚举数组。七项明确指定钓组的任务保持原字段。
- 6502 使用钓组 12/13/14/15/17；7401 要求五种人面鲤；7502 使用九种底部发丝钓组，包含 16。
  完成数量与独立显示修复使用的 168 项永久目标一致。
- 在结算事务开始前读取活动范围，避免持有写锁时经其他连接查询参数；计数与奖杯共用范围判断。
  历史完成状态和已发奖杯不自动删除。
- 咬钩快照新增可选 bite_unix，持久化仍使用现有 JSON；12301 按 23:00（含）到 04:00（不含）判断。
  旧快照缺少准确时间时不使用结算时间替代。
- 20602/20603 的两尾星鱼与两种罕见鱼种路径分别在现有 kv 中保存证据，与本尾结算同事务提交；
  只将较大单路径进度写回原计数器。该条件按任务文案实现，尚未与官方结构化活动定义核对。
- 额外鱼绑定原竿、各自的饵快照及同次咬钩时间，进入已有资格结算；同一任务以最终累计进度下发。
  所有鱼结算后巡检奖杯，重复 14/4 从现有 Batch 和回执恢复额外鱼结果，不重复扣饵。
- 基于已合入条件显示修复 e0a2543（PR #512）的主干继续修正判定；新增手竿显示断言
  位于专用测试文件，不重复提交条件显示的代码或静态表。
- 保留上游活动阶段礼物的既有非重放条件和发放机制，将巡检放在所有鱼结算后。

## Out of Scope

32 条缺失真实信号的活动任务继续隐藏；不补造未知名单、累计总重或其他缺口条件。
不重算历史进度，不包含存档清理脚本、个人玩法、客户端桥接或条件显示修复本身。

# 九周年阶段与完成奖励

Status: done

## Problem Statement

活动任务存在，但未配置阶段物品，整条任务线完成后也只发奖杯，无法获得九周年预览中的纪念装备和会员。

## Solution

在上游活动奖励编辑器提供九周年分支 19/20 的奖励预设，只填充未配置阶段，用户检查并保存后才生效；不在升级或启动时写入默认奖励。完成阶段自动发放，全部完成后补发额外装备及三天会员。历史已完成进度巡检补发一次，重新登录或重复结算不重复领取。

使用：后台「游戏参数 → 限时活动」开启活动并保存包含 19/20 的分支列表，选择「九周年（2026）」并点击「填入所选预设」，检查或修改各阶段以及「全部完成额外奖励」，点击「保存全部奖励」。完全退出并重启游戏客户端后加载新预览。只启用 19 时只填 19，稍后启用 20 可再次填入而不覆盖已有配置。年份选择与历史预设扩展见[历年活动预设](../historical-event-reward-presets/spec.md)。

## User Stories

1. 玩家完成相应阶段获得对应礼盒、饮品或装备，打开礼盒获得静态配置内容。
2. 普通版全部完成获得纪念手竿、三天会员与原有奖杯；特别版全部完成获得纪念轮与原有奖杯。
3. 活动关闭、分支隐藏或活动已结束不发奖；失败不留下领取标记；永久会员不被降级。
4. 已有自定义阶段、未保存的编辑和其他分支奖励不被预设覆盖；只有启用且可编辑的九周年分支可以填入。页面说明补发行为、数量口径和未验证部分。

## Implementation Decisions

- 沿用 `event_stage_gifts`：1..N 是阶段，0 是全部阶段完成的额外奖励。管理端支持 0，预设置于 `internal/admin/web/event-reward-presets/anniversary-2026.json` 并随 WebFS 内嵌发布，不增加写接口或配置真源。
- `event_switches.go` 的 5009.f4 展示 stage 0 目录键并附原有奖杯；5008.f2 沿用阶段预览。`tools/proto.ps1 class bibmoppiacg` / `goglkgnhpcl` 核对字段为 VAL，真实响应确认 UTF8 string[]，不改 args code。基线客户端 4.0.25034。
- 发放复用阶段 kv 标记与经济事务，不加表。会员 `premium_3d` 直接延长 profile 时长，和同批物品/标记同事务，沿用 refresh_player 队列刷新客户端。奖杯仍使用已有独立事务及标记，失败后下次巡检恢复。
- 先补回归测试，再实现阶段 0 / 会员与配置，测试真实礼盒拆包，最后运行门禁并部署。回滚前备份运行配置与二进制；已发奖励不会因回滚再次撤回。
- 实施顺序：预设资源与数量验证 → 管理页填入/保存/重载回归 → 完成奖励及会员的续期/回滚/并发测试 → 上游回归和代码评审。继续复用现有阶段发奖与奖杯机制。

## Testing Decisions

- 真实 SQLite：未完成不发、阶段与全部完成隔离、重放、已有奖杯、会员续期/过期/永久/事务回滚、活动过期。
- 协议：固定字面量断言 5009.f4 / 5008.f2 并编解码回环。
- 真实静态库：所有奖励可构造，礼盒按固定期望内容与数量打开，重复使用不增发。
- 管理端 stage 0 保存与 UI 切换回归；全量 go test / vet / build / doccheck。

验证结果（2026-11-17）：`go test ./... -parallel 4` 全部通过（gameserver 221.399s）；`go vet ./...`、`go build ./...` 通过；doccheck issues=0，既有 bite 能力文档长度软提示 1 条。Playwright `internal/admin/event_stage_gifts_ui_test.cjs` 在 1280/360 宽度通过，覆盖 stage 0、填入预设不保存、保留已保存/未保存自定义配置、重复填入及后续启用第二分支。独立代码评审无阻塞问题。客户端实机奖励显示及领取未验证。

## Out of Scope

未取得证据的七/八周年和新年奖励；修改玩家任务完成状态；模拟官服隐藏实例属性。

# 双支线饵位与换钓组配件归属

Status: done

## Problem Statement

普通海洋底部钓组（55）和带响珠型（56）有两条固定支线，客户端分别用钩位 250/251 和天然饵位 350/351。旧实现把第二份天然饵的索引也规范化为 350，导致第二钩装饵后客户端仍显示空槽，读档后也无法恢复。

玩家主动切换钓组时，旧实现还会按“新模板也有同品类槽位”保留钩、饵、拟饵等末端配件，形成新钓组外观但旧配件仍挂载的混合状态。

## Solution

对 rig 55/56 固定使用天然饵索引 350/351，并在读档时就按原数组顺序恢复旧档中的两个 350 饵位。玩家主动切换钓组时，只保留竿侧通用部件和主震子线；钩、饵、拟饵、沉子、食笼与 150–152 支线退回背包，同时清理旧钓组的待补饵记录。登录或旧档类型校正仍使用兼容保留规则。

## User Stories

1. rig 55/56 两个钩位可分别显示和保存天然饵，第一饵消耗后自动补回对应空槽，不覆盖第二饵。
2. 旧档若已保存两个天然饵且索引均为 350，读档后按原顺序恢复为 350/351，无需数据库迁移。
3. 玩家主动换型时，竿体、灵敏梢、渔轮和主线保留；目标模板支持 175 槽时，震子线保留。
4. 旧钓组的钩、饵、拟饵、沉子、食笼与 150–152 支线退回背包，不再污染新钓组。
5. 两钩同堆拆出的饵退回时，来源堆显示最终剩余数量，不出现重复或回退。
6. 登录自动校正和重选当前钓组不会触发主动换型拆卸。

## Implementation Decisions

- `hasFixedMarineBaitSlots` 限定 rig 55/56；天然饵规范索引为 350/351，`rigCompsOf` 对旧档重复 350 按数组顺序恢复 ordinal 0/1。
- 自动补饵在 rig 55/56 按目标钩 250/251 映射到对应饵位，不能按已装饵数量追加。
- 17/1 玩家显式换型调用 `mutateRodRig(..., playerSwitch=true)`；登录/校正路径保持 `playerSwitch=false`，继续使用前后模板兼容规则。
- 玩家换型保留 f3/f4 主线、渔轮、竿坯/手柄/导环、灵敏梢、包装盒，以及目标模板支持的 175 震子线；其他末端组件退回背包。
- 主动换型清除该竿的 `rebait:*`、`refill:*`、`bait_hook:*` 待处理记录，避免旧钓组补饵跨到新钓组。
- 同源拆分子实例退回时按剩余数量累加来源堆，并让响应快照移除被清理的挂载 GUID；来源堆用最终树做 4/21→4/22 刷新。
- 不改协议字段、args code、表结构或迁移，客户端基线仍为 4.0.25034。

## Testing Decisions

- 真实静态库与临时玩家库验证 rig 55/56 两钩同堆装饵、独立替换/卸下第二饵、第一饵耗尽后补位。
- 构造旧档两份索引均为 350 的 f5，验证重建顺序为 350/351。
- 验证 55→56、56→55 换型时两只饵退回，来源堆数量正确，旧补饵/挂饵设置被清理，无关设置保留。
- 验证 `55→58→56→57→55` 连续换型始终保留同一震子线、渔轮和主线，旧支线/钩/饵不残留。
- 保留现有 rig 多钩、单钩双饵、去重索引、耐久与断件测试。
- 门禁：`go test ./...`、`go vet ./...`、`go build ./...`、`go run ./tools/doccheck`。

## Out of Scope

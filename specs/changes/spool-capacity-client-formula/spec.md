# 线杯容量按客户端分段公式计算

Status: done

## Problem Statement

服务端用 `0.093 × 系数 / 线径^1.65` 估算线杯容量，只在细线锚点附近成立。
粗线会明显低估：0.7mm / 系数 100 的轮子游戏内显示 34m，服务端只算出
16.75m；0.42mm / 系数 120 的轮子游戏内显示 91m，服务端只算出 58.56m。
线杯容量偏低会同时影响 `LineLimitM`、上杯率和抛投距离。

## Solution

按客户端 `lkgakdhinig.jnidmcfnkgp` 的分段公式计算容量：

```text
d <= 0.25      C = coef * 0.10153155 / d^1.65
0.25 < d < 0.8 C = coef * 0.10153155 / d^(1.65 + 2.2*t)
d >= 0.8       C = coef * 0.16588345 / d^1.65
t = clamp((d - 0.25) / 0.55, 0, 1)
```

结果向下取整，且不小于 5m。

## Testing Decisions

- 实机 UI 锚点：Overlord 3RS 20S（`spin_5425`）`0.70mm / 34m`、Adriatica 3000S（`spin_5026`）`0.42mm / 91m`。
- 静态物品端到端断言：从轮子默认线杯读取 `djcepbpigpe`，从线材读取实际线径，避免同系列不同 20S 型号混用。
- 细线/粗线公式回归与边界用例：`0.25`、`0.80`、`>0.80` 以及 5m 下限。
- 回滚后上述两个实机锚点会变红。

## Out of Scope

- 不修改主线实例长度，不重新引入线长收口。
- 不调整抛投基准、竿长/载荷/线杯距离修正器。
